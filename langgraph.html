LangGraph Complete Guide

🧭 What is LangGraph?

LangGraph is a library from the LangChain team for building stateful AI agents and workflows as graphs. Steps are nodes, connections are edges, and a shared state flows through them.
Why was LangGraph created?

LangChain chains run in a straight line: A → B → C. Real agents need more:

  • 🔁 Loops: call a tool, look at the result, maybe call another tool…
  • 🔀 Branching: go to a different step depending on the result
  • 💾 Persistence: remember everything, even after a crash or restart
  • 🙋 Human-in-the-loop: pause and wait for a person to approve
  • 👥 Multiple agents working together
  • 🎛️ Full control: you decide exactly how the agent behaves
The 3 Core Concepts
📦 State
Shared data (a TypedDict) that every node can read & update
+
⚙️ Nodes
Python functions: take state, return updates
+
➡️ Edges
Decide which node runs next (fixed or conditional)

Special nodes: START (entry point) and END (finish). You build the graph with StateGraph, then .compile() it into a runnable app.

Your First Graph
from typing import TypedDict from langgraph.graph import StateGraph, START, END # 1. Define the state class State(TypedDict): text: str # 2. Define nodes (functions that return state updates) def uppercase(state: State): return {"text": state["text"].upper()} def add_exclaim(state: State): return {"text": state["text"] + "!"} # 3. Build the graph builder = StateGraph(State) builder.add_node("uppercase", uppercase) builder.add_node("add_exclaim", add_exclaim) builder.add_edge(START, "uppercase") builder.add_edge("uppercase", "add_exclaim") builder.add_edge("add_exclaim", END) # 4. Compile & run graph = builder.compile() print(graph.invoke({"text": "hello"})) # {'text': 'HELLO!'}
START ──▶ uppercase ──▶ add_exclaim ──▶ END
How it runs: the graph starts at START, runs each node, and merges the dictionary each node returns into the state. A node only returns the keys it wants to change. When it reaches END, the final state is returned.

📦 State & Reducers

The state is the memory of one graph run. A reducer decides how a node's update is combined with the existing value.
Default: Overwrite
class State(TypedDict): question: str answer: str # a node returning {"answer": "42"} REPLACES the old answer
With a Reducer: Append / Combine
import operator from typing import Annotated, TypedDict class State(TypedDict): question: str # overwritten steps: Annotated[list[str], operator.add] # new items are APPENDED def step_a(state: State): return {"steps": ["searched the web"]} def step_b(state: State): return {"steps": ["wrote the answer"]} # final state["steps"] == ["searched the web", "wrote the answer"]
Messages State with add_messages ✅ used for every chatbot / agent
from typing import Annotated, TypedDict from langgraph.graph.message import add_messages class State(TypedDict): messages: Annotated[list, add_messages] # Even shorter: the built-in MessagesState is exactly this from langgraph.graph import MessagesState class MyState(MessagesState): # extend it with your own fields user_name: str documents: list[str]
add_messages is smarter than operator.add: it appends new messages, updates a message if one with the same ID already exists, and converts dicts like {"role": "user", "content": "hi"} into proper message objects.
Input / Output Schemas (optional)
class InputState(TypedDict): question: str class OutputState(TypedDict): answer: str class OverallState(InputState, OutputState): notes: list[str] # internal only, hidden from the caller builder = StateGraph(OverallState, input_schema=InputState, output_schema=OutputState)
Tips for Designing State
  • Keep it small: store only what nodes need.
  • Use reducers for anything that accumulates (messages, logs, results from parallel nodes).
  • Pydantic models or dataclasses also work if you want validation.

🔀 Nodes, Edges, Branching & Loops

Types of Edges
EdgeCodeBehaviour
Normaladd_edge("a", "b")Always go from a to b
Conditionaladd_conditional_edges("a", fn)A function looks at the state and picks the next node
Entryadd_edge(START, "a")Where the graph starts
Finishadd_edge("a", END)Stop the graph
Fan-outadd_edge(START, "a") + add_edge(START, "b")a and b run in parallel
Conditional Edge + Loop: Retry Until Good
import random from typing import TypedDict from langgraph.graph import StateGraph, START, END class State(TypedDict): attempts: int answer: str def generate(state: State): return {"attempts": state["attempts"] + 1, "answer": random.choice(["good", "bad"])} def check_quality(state: State) -> str: # the router function if state["answer"] == "good" or state["attempts"] >= 3: return "done" return "retry" builder = StateGraph(State) builder.add_node("generate", generate) builder.add_edge(START, "generate") builder.add_conditional_edges( "generate", check_quality, {"retry": "generate", "done": END}, # map router output -> next node ) graph = builder.compile() graph.invoke({"attempts": 0, "answer": ""})
START ──▶ generate ──▶ (check_quality) ▲ │ └──── "retry" ───┤ └── "done" ──▶ END
⚠️ Recursion limit: to stop infinite loops, a graph stops after 25 steps by default and raises GraphRecursionError. Change it with graph.invoke(inputs, {"recursion_limit": 50}).
Command: Update State AND Jump in One Step
from typing import Literal from langgraph.types import Command def router(state: State) -> Command[Literal["math_node", "chat_node"]]: if any(ch.isdigit() for ch in state["question"]): return Command(update={"route": "math"}, goto="math_node") return Command(update={"route": "chat"}, goto="chat_node")
Parallel Nodes (Fan-out / Fan-in)
class State(TypedDict): topic: str results: Annotated[list[str], operator.add] # reducer needed to merge parallel writes builder.add_edge(START, "search_web") builder.add_edge(START, "search_docs") # both run at the same time builder.add_edge("search_web", "combine") builder.add_edge("search_docs", "combine") # combine waits for both builder.add_edge("combine", END)
Subgraphs

A compiled graph can be used as a node inside another graph. This is great for splitting a big agent into reusable parts.

research_graph = research_builder.compile() main_builder.add_node("research", research_graph) # whole graph as one node

💬 Building a Chatbot

The simplest real LangGraph app: one node that calls the LLM with all messages in the state.
from langgraph.graph import StateGraph, MessagesState, START, END from langchain_openai import ChatOpenAI # from langchain_ollama import ChatOllama # free local alternative llm = ChatOpenAI(model="gpt-4o-mini", temperature=0) def chatbot(state: MessagesState): reply = llm.invoke(state["messages"]) return {"messages": [reply]} # add_messages appends it builder = StateGraph(MessagesState) builder.add_node("chatbot", chatbot) builder.add_edge(START, "chatbot") builder.add_edge("chatbot", END) graph = builder.compile() result = graph.invoke({"messages": [{"role": "user", "content": "Hi! What is LangGraph?"}]}) print(result["messages"][-1].content)
Adding a System Prompt
from langchain_core.messages import SystemMessage SYSTEM = SystemMessage(content="You are a friendly AI tutor. Explain simply.") def chatbot(state: MessagesState): return {"messages": [llm.invoke([SYSTEM] + state["messages"])]}
Chat Loop in the Terminal
while True: user = input("You: ") if user.lower() in {"quit", "exit"}: break result = graph.invoke({"messages": [{"role": "user", "content": user}]}) print("Bot:", result["messages"][-1].content)
⚠️ Problem: this bot forgets everything between invoke() calls, because each call starts with a fresh state. The fix is a checkpointer; see the Memory & Persistence tab.

🛠️ Tools & the ReAct Agent

A ReAct agent loops: LLM thinks → calls a tool → reads the result → thinks again, until it can answer without tools.
START ──▶ agent ──(tool_calls?)── yes ──▶ tools ▲ │ └──────────────────────────────────┘ no ──▶ END
Building it from Scratch
from langchain_core.tools import tool from langchain_openai import ChatOpenAI from langgraph.graph import StateGraph, MessagesState, START from langgraph.prebuilt import ToolNode, tools_condition @tool def get_weather(city: str) -> str: """Get the current weather for a city.""" return f"It's 28°C and sunny in {city}." @tool def multiply(a: int, b: int) -> int: """Multiply two numbers.""" return a * b tools = [get_weather, multiply] llm_with_tools = ChatOpenAI(model="gpt-4o-mini").bind_tools(tools) def agent(state: MessagesState): return {"messages": [llm_with_tools.invoke(state["messages"])]} builder = StateGraph(MessagesState) builder.add_node("agent", agent) builder.add_node("tools", ToolNode(tools)) # runs whatever tools the LLM asked for builder.add_edge(START, "agent") builder.add_conditional_edges("agent", tools_condition) # -> "tools" or END builder.add_edge("tools", "agent") # loop back after tools run graph = builder.compile() result = graph.invoke({"messages": [ {"role": "user", "content": "Weather in Hyderabad? Also what is 12 x 7?"} ]}) for m in result["messages"]: m.pretty_print()
What each piece does
  • bind_tools: tells the LLM which tools exist (name, description, arguments).
  • ToolNode: a prebuilt node that executes the tool calls and returns ToolMessages.
  • tools_condition: a prebuilt router: if the last message has tool_calls go to "tools", else go to END.
The Prebuilt Shortcut
# LangChain 1.0+ (built on LangGraph) from langchain.agents import create_agent agent = create_agent("openai:gpt-4o-mini", tools=tools, system_prompt="You are helpful.") # Older LangGraph versions from langgraph.prebuilt import create_react_agent agent = create_react_agent(ChatOpenAI(model="gpt-4o-mini"), tools) agent.invoke({"messages": [{"role": "user", "content": "What is 6 x 9?"}]})
When to build from scratch? Use the prebuilt agent for standard tool-calling. Build your own graph when you need custom steps, e.g. a "check the answer" node, approval before certain tools, or a planning step before acting.

🧠 Memory & Persistence

A checkpointer saves the state after every step. Give each conversation a thread_id and the graph remembers it across calls.
Short-term Memory (per conversation)
from langgraph.checkpoint.memory import InMemorySaver graph = builder.compile(checkpointer=InMemorySaver()) config = {"configurable": {"thread_id": "sai-chat-1"}} graph.invoke({"messages": [{"role": "user", "content": "Hi, I'm Sai"}]}, config) result = graph.invoke({"messages": [{"role": "user", "content": "What's my name?"}]}, config) print(result["messages"][-1].content) # "Your name is Sai" ✅ # a different thread = a brand-new conversation graph.invoke({"messages": [{"role": "user", "content": "What's my name?"}]}, {"configurable": {"thread_id": "other-user"}}) # "I don't know" ✅
Checkpointer Options
CheckpointerPackageUse for
InMemorySaverbuilt inLearning & testing (lost on restart)
SqliteSaverlanggraph-checkpoint-sqliteLocal apps, saved to a file

Inspecting & Time Travel
snapshot = graph.get_state(config) print(snapshot.values) # current state print(snapshot.next) # which node runs next (if paused) for past in graph.get_state_history(config): # every saved step print(past.config, past.values.get("messages", [])[-1:]) # Replay / fork from an older step graph.invoke(None, past.config) # Manually edit the state graph.update_state(config, {"messages": [{"role": "user", "content": "Actually, call me Sai Kiran"}]})
Long-term Memory (across conversations): the Store
from langgraph.store.memory import InMemoryStore store = InMemoryStore() store.put(("users", "sai"), "preferences", {"language": "Python", "level": "beginner"}) graph = builder.compile(checkpointer=InMemorySaver(), store=store) # inside a node you can read it: # def node(state, *, store): prefs = store.get(("users", "sai"), "preferences")

Keeping Long Chats Small
  • Trim: use trim_messages to send only the last N tokens to the LLM.
  • Delete: return RemoveMessage(id=...) to remove old messages from state.
  • Summarize: add a node that summarizes old messages when the list gets long (like ConversationSummaryBufferMemory).

🙋 Human-in-the-Loop

Pause the graph, show something to a person, and continue only after they respond. This is essential for risky actions like sending emails, payments or deleting data.
Draft
Agent prepares an action
→
⏸️ interrupt()
Graph pauses & saves state
→
Human
Approves / edits / rejects
→
▶️ Resume
Command(resume=…)
Dynamic interrupt() ✅ recommended
from typing import TypedDict from langgraph.graph import StateGraph, START, END from langgraph.types import interrupt, Command from langgraph.checkpoint.memory import InMemorySaver class State(TypedDict): draft: str approved: bool def write_email(state: State): return {"draft": "Hi team, the model training finished successfully."} def human_review(state: State): decision = interrupt({"question": "Send this email?", "draft": state["draft"]}) return {"approved": decision == "yes"} def send_email(state: State): print("📧 Sent!" if state["approved"] else "❌ Cancelled") return {} builder = StateGraph(State) builder.add_node("write_email", write_email) builder.add_node("human_review", human_review) builder.add_node("send_email", send_email) builder.add_edge(START, "write_email") builder.add_edge("write_email", "human_review") builder.add_edge("human_review", "send_email") builder.add_edge("send_email", END) graph = builder.compile(checkpointer=InMemorySaver()) # a checkpointer is REQUIRED config = {"configurable": {"thread_id": "email-1"}} result = graph.invoke({"draft": "", "approved": False}, config) print(result["__interrupt__"]) # shows the question & draft, graph is paused graph.invoke(Command(resume="yes"), config) # 📧 Sent!
Common Patterns
  • Approve / reject a tool call before it runs.
  • Edit: let the human change the draft, then continue with the edited version.
  • Ask for missing info: "Which date should I book?"
  • Review the final answer before showing it to a customer.
Static Breakpoints (for debugging)
graph = builder.compile(checkpointer=InMemorySaver(), interrupt_before=["tools"]) graph.invoke(inputs, config) # stops before the "tools" node graph.invoke(None, config) # continue

👥 Multi-Agent Systems

Instead of one agent with 20 tools, use several specialist agents, each with a few tools and a focused prompt, and let them work together.
Architectures
PatternHow it worksGood for
👔 SupervisorA manager agent decides which worker runs nextClear task delegation (research → write → review)
🐝 Swarm / NetworkAgents hand off directly to each otherCustomer support (sales ↔ billing ↔ tech)
🏢 HierarchicalSupervisors of supervisors (teams of teams)Large, complex projects

Supervisor Example
from typing import Literal from pydantic import BaseModel from langchain_openai import ChatOpenAI from langchain.agents import create_agent from langgraph.graph import StateGraph, MessagesState, START, END from langgraph.types import Command llm = ChatOpenAI(model="gpt-4o-mini") research_agent = create_agent(llm, tools=[web_search], system_prompt="You find facts.") writer_agent = create_agent(llm, tools=[], system_prompt="You write clear answers.") class Route(BaseModel): next: Literal["researcher", "writer", "FINISH"] def supervisor(state: MessagesState) -> Command[Literal["researcher", "writer", "__end__"]]: route = llm.with_structured_output(Route).invoke( [{"role": "system", "content": "You manage a researcher and a writer. Pick who acts next, or FINISH when done."}] + state["messages"] ) return Command(goto=END if route.next == "FINISH" else route.next) def researcher(state: MessagesState) -> Command[Literal["supervisor"]]: result = research_agent.invoke(state) return Command(goto="supervisor", update={"messages": [result["messages"][-1]]}) def writer(state: MessagesState) -> Command[Literal["supervisor"]]: result = writer_agent.invoke(state) return Command(goto="supervisor", update={"messages": [result["messages"][-1]]}) builder = StateGraph(MessagesState) builder.add_node("supervisor", supervisor) builder.add_node("researcher", researcher) builder.add_node("writer", writer) builder.add_edge(START, "supervisor") graph = builder.compile()
┌──────────────┐ START ──▶ │ supervisor │ ──▶ END └──┬────────▲──┘ goto │ │ back ┌──────▼──┐ ┌──┴──────┐ │researcher│ │ writer │ └──────────┘ └─────────┘
Shortcut packages: langgraph-supervisor (create_supervisor) and langgraph-swarm (create_swarm) build these patterns for you in a few lines.

Deployment & Tools
  • LangGraph Studio: a visual IDE to see your graph run step by step, inspect state and test interrupts. Start it with langgraph dev (from pip install "langgraph-cli[inmem]").
  • langgraph.json: config file that tells the CLI where your graph is.
  • LangSmith Deployment (LangGraph Platform): hosts your graph as an API with built-in persistence, streaming and task queues.
  • Self-host: wrap graph.invoke in FastAPI / Flask and use a Postgres checkpointer.
  • LangSmith tracing: set LANGSMITH_TRACING=true to see every node, LLM call and tool call.

📋 LangGraph Cheat Sheet

Most-used Imports
from langgraph.graph import StateGraph, MessagesState, START, END from langgraph.graph.message import add_messages from langgraph.prebuilt import ToolNode, tools_condition from langgraph.checkpoint.memory import InMemorySaver from langgraph.store.memory import InMemoryStore from langgraph.types import Command, interrupt from langchain.agents import create_agent # prebuilt agent (LangChain 1.0)
The Recipe
  1. Define State (TypedDict / MessagesState, add reducers for lists)
  2. Write node functions: def node(state) -> dict
  3. builder = StateGraph(State) and add_node for each node
  4. Connect with add_edge / add_conditional_edges
  5. graph = builder.compile(checkpointer=...)
  6. Run with invoke / stream and a thread_id

Best Practices
  • 🧩 Keep each node small and focused on one job.
  • 🔁 Always have an exit condition for loops (and remember the recursion limit).
  • 💾 Use a real checkpointer (SQLite / Postgres) outside of learning.
  • 🙋 Put interrupt() before any irreversible action.
  • ✂️ Trim or summarize messages so long chats don't blow the context window.
  • 🔍 Use LangGraph Studio + LangSmith to see exactly what your agent did.
  • 🦜 Use LangChain components (models, retrievers, tools) inside your nodes.
