LangChain Complete Guide

🧭 What is LangChain?

LangChain is an open-source framework (Python & JavaScript) for building apps powered by Large Language Models. It gives you ready-made, swappable building blocks so you don't have to write the glue code yourself.
Why use LangChain?
  • One interface for every model: switch from OpenAI to Gemini, Claude or a free local LLaMA by changing one line.
  • Connect LLMs to your data: PDFs, websites, databases (RAG).
  • Let LLMs take actions: call tools like search, calculators and APIs (agents).
  • Composable: join steps with the | pipe operator (LCEL).
  • Huge ecosystem: hundreds of integrations for models, vector stores, loaders and tools.

Add-ons around that core: Retrievers (fetch your data), Tools (actions), Memory (chat history), and Agents (LLM decides which tools to use).

Your First Chain
from langchain_core.prompts import ChatPromptTemplate from langchain_core.output_parsers import StrOutputParser from langchain_openai import ChatOpenAI prompt = ChatPromptTemplate.from_template("Explain {topic} to a beginner in 3 lines.") llm = ChatOpenAI(model="gpt-4o-mini", temperature=0) chain = prompt | llm | StrOutputParser() print(chain.invoke({"topic": "neural networks"}))
📌 Version note: LangChain 1.0 (Oct 2025) simplified the library: agents are built with create_agent, and old classes like ConversationChain, LLMChain and the memory classes moved to langchain-classic. Everything in langchain-core (prompts, LCEL, parsers, tools) works the same in both versions.

🤖 Models & Messages

LangChain wraps every provider in the same interface, so invoke(), stream() and batch() work for all of them.
LLMs vs Chat Models

LLM (text-in, text-out)

Input: a plain string
Output: a plain string
Older style, rarely used now

Chat Model (messages-in, message-out)

Input: a list of messages
Output: an AIMessage
✅ Use this for all modern models
Message Types
MessageRolePurpose
SystemMessagesystemSets behavior / persona ("You are a helpful AI tutor")
HumanMessageuserWhat the user says
AIMessageassistantThe model's reply (may contain tool_calls)
ToolMessagetoolThe result of a tool call, sent back to the model
from langchain_openai import ChatOpenAI from langchain_core.messages import SystemMessage, HumanMessage llm = ChatOpenAI(model="gpt-4o-mini", temperature=0) messages = [ SystemMessage(content="You are a helpful AI tutor."), HumanMessage(content="What is overfitting?"), ] response = llm.invoke(messages) print(response.content) # the text reply print(response.usage_metadata) # input / output token counts # Shortcut: tuples or dicts work too llm.invoke([("system", "Answer in one line."), ("human", "What is ML?")])
Swapping Providers
from langchain_openai import ChatOpenAI from langchain_google_genai import ChatGoogleGenerativeAI from langchain_ollama import ChatOllama # free, runs on your PC llm = ChatOpenAI(model="gpt-4o-mini") llm = ChatGoogleGenerativeAI(model="gemini-2.0-flash") llm = ChatOllama(model="llama2") # or one helper for all providers: from langchain.chat_models import init_chat_model llm = init_chat_model("gpt-4o-mini", model_provider="openai")
Important Parameters
  • temperature: 0 = focused & repeatable, 1 = creative & random
  • max_tokens: limit the length of the reply
  • timeout / max_retries: handle slow or failed API calls
invoke vs stream vs batch
llm.invoke("What is AI?") # one input -> one full answer for chunk in llm.stream("Explain RAG"): # tokens arrive one by one (typing effect) print(chunk.content, end="", flush=True) llm.batch(["What is ML?", "What is DL?"]) # many inputs in parallel -> list of answers await llm.ainvoke("Hi") # async versions: ainvoke / astream / abatch

📝 Prompt Templates

A prompt template is a reusable prompt with {placeholders} that get filled in at run time.
1. PromptTemplate (plain text)
from langchain_core.prompts import PromptTemplate prompt = PromptTemplate.from_template("Explain {topic} to a {level} in simple words.") print(prompt.invoke({"topic": "embeddings", "level": "10 year old"}).to_string()) # Explain embeddings to a 10 year old in simple words.
2. ChatPromptTemplate (list of messages) ✅ most used
from langchain_core.prompts import ChatPromptTemplate prompt = ChatPromptTemplate.from_messages([ ("system", "You are an expert in {subject}. Keep answers short."), ("human", "{question}"), ]) prompt.invoke({"subject": "deep learning", "question": "What is a CNN?"})
3. MessagesPlaceholder (insert a list of messages, e.g. chat history)
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder prompt = ChatPromptTemplate.from_messages([ ("system", "You are a helpful assistant."), MessagesPlaceholder("history"), # past conversation goes here ("human", "{question}"), ])
4. Few-Shot Prompts (teach by example)
from langchain_core.prompts import ChatPromptTemplate, FewShotChatMessagePromptTemplate examples = [ {"input": "happy", "output": "sad"}, {"input": "tall", "output": "short"}, ] example_prompt = ChatPromptTemplate.from_messages([("human", "{input}"), ("ai", "{output}")]) few_shot = FewShotChatMessagePromptTemplate(examples=examples, example_prompt=example_prompt) prompt = ChatPromptTemplate.from_messages([ ("system", "Give the opposite of each word."), few_shot, ("human", "{input}"), ]) chain = prompt | llm chain.invoke({"input": "fast"}).content # -> "slow"
5. Partial Variables (pre-fill some values)
prompt = PromptTemplate.from_template("Today is {date}. {question}") prompt_today = prompt.partial(date="17 Nov 2026") prompt_today.invoke({"question": "What day is it?"})
💡 Tips: put rules & persona in the system message, keep variables descriptive, and use few-shot examples when you need a specific format or style. You can also pull ready-made prompts from the LangChain Hub.

📦 Output Parsers & Structured Output

Models return an AIMessage. Output parsers turn it into something your code can use: a string, a dict, a list or a Python object.
StrOutputParser: just the text
from langchain_core.output_parsers import StrOutputParser chain = prompt | llm | StrOutputParser() chain.invoke({"topic": "RAG"}) # -> "RAG stands for ..." (a plain str)
JsonOutputParser: a dictionary
from langchain_core.output_parsers import JsonOutputParser prompt = ChatPromptTemplate.from_template( "Return JSON with keys 'name' and 'use_case' for the AI framework {framework}." ) chain = prompt | llm | JsonOutputParser() chain.invoke({"framework": "LangGraph"}) # {'name': 'LangGraph', 'use_case': 'Building stateful agents'}
with_structured_output(): ✅ the recommended way

Define the shape you want with Pydantic; the model is forced to fill it in (uses the provider's native JSON / tool-calling support).

from pydantic import BaseModel, Field class Review(BaseModel): sentiment: str = Field(description="positive, negative or neutral") score: int = Field(description="rating from 1 to 5") summary: str = Field(description="one-line summary") structured_llm = llm.with_structured_output(Review) result = structured_llm.invoke("The course was great but a bit too fast.") print(result.sentiment, result.score) # positive 4 print(result.summary)
Other Parsers
ParserReturns
PydanticOutputParserA Pydantic object (adds format instructions to the prompt; for models without native structured output)
CommaSeparatedListOutputParserA Python list from "a, b, c"
XMLOutputParserA dict from XML output
OutputFixingParserAsks the LLM to fix output that failed to parse

🔗 LCEL: LangChain Expression Language

Every component is a Runnable. Join Runnables with | and the output of one becomes the input of the next.
Every Runnable has the same methods
MethodWhat it does
invoke(input)Run once, get the full result
stream(input)Get the result piece by piece
batch([inputs])Run many inputs in parallel
ainvoke / astream / abatchAsync versions
RunnableParallel: run branches at the same time
from langchain_core.runnables import RunnableParallel summary = ChatPromptTemplate.from_template("Summarize: {text}") | llm | StrOutputParser() keywords = ChatPromptTemplate.from_template("List 5 keywords: {text}") | llm | StrOutputParser() both = RunnableParallel(summary=summary, keywords=keywords) result = both.invoke({"text": "LangChain is a framework for ..."}) print(result["summary"], result["keywords"]) # A plain dict inside a chain is automatically a RunnableParallel: chain = {"summary": summary, "keywords": keywords} | some_next_step
RunnablePassthrough: pass the input along unchanged
from langchain_core.runnables import RunnablePassthrough chain = {"context": retriever, "question": RunnablePassthrough()} | prompt | llm chain.invoke("What is LoRA?") # the question goes to the retriever AND to the prompt # .assign() adds new keys and keeps the old ones chain = RunnablePassthrough.assign(word_count=lambda x: len(x["text"].split())) chain.invoke({"text": "hello world"}) # {'text': 'hello world', 'word_count': 2}
RunnableLambda: use any Python function
from langchain_core.runnables import RunnableLambda to_upper = RunnableLambda(lambda text: text.upper()) chain = prompt | llm | StrOutputParser() | to_upper
Routing / Branching
math_chain = ChatPromptTemplate.from_template("Solve step by step: {q}") | llm general_chain = ChatPromptTemplate.from_template("Answer briefly: {q}") | llm def route(inputs): if any(ch.isdigit() for ch in inputs["q"]): return math_chain return general_chain chain = RunnableLambda(route) # a function that returns a Runnable = router chain.invoke({"q": "What is 25 * 4?"})
Useful extras
  • chain.with_retry(stop_after_attempt=3): retry on errors
  • chain.with_fallbacks([backup_chain]): use another model if one fails
  • llm.bind(stop=["\n"]): fix some arguments in advance
  • chain.get_graph().print_ascii(): draw the chain

🧠 LangChain Memory & ConversationChain

Why memory? LLMs are stateless: each call forgets the previous one. Memory classes store the chat history and add it to every new prompt, so the bot can remember what you said earlier.

💬 ConversationChain

The simplest chain for chatting. It connects an LLM, a prompt (with a {history} slot), and a memory object. On every turn it:

1. Load
Read past messages from memory
→
2. Prompt
History + new input sent to the LLM
→
3. Save
Store the input & reply back in memory
from langchain_openai import ChatOpenAI from langchain.chains import ConversationChain from langchain.memory import ConversationBufferMemory llm = ChatOpenAI(model="gpt-4o-mini", temperature=0) conversation = ConversationChain(llm=llm, memory=ConversationBufferMemory(), verbose=True) conversation.predict(input="Hi, my name is Sai") conversation.predict(input="What is my name?") # -> "Your name is Sai"

1️⃣ ConversationBufferMemory

Stores the entire conversation word for word and sends all of it with every prompt.

✅ Pros

• Nothing is ever lost
• Simple and exact

⚠️ Cons

• Prompt grows every turn
• More tokens = higher cost
• Can exceed the context window
from langchain.memory import ConversationBufferMemory memory = ConversationBufferMemory() memory.save_context({"input": "Hi"}, {"output": "Hello! How can I help?"}) print(memory.load_memory_variables({})) # {'history': 'Human: Hi\nAI: Hello! How can I help?'}

Best for: short chats and demos.

2️⃣ ConversationBufferWindowMemory

Keeps only the last k exchanges (a sliding window). Older messages are dropped.

Example (k=2): after 5 turns, only turns 4 and 5 are sent to the LLM. Turns 1 to 3 are forgotten.
from langchain.memory import ConversationBufferWindowMemory memory = ConversationBufferWindowMemory(k=2) # remember last 2 exchanges

Best for: long chats where only recent context matters. Downside: it forgets early details like the user's name.

3️⃣ ConversationSummaryMemory

Instead of storing raw messages, it uses an LLM to write a running summary of the conversation and updates it after each turn.

Stored history: "The user, Sai, is learning AI and asked how transformers work. The AI explained self-attention."
from langchain.memory import ConversationSummaryMemory memory = ConversationSummaryMemory(llm=llm) # needs an LLM to summarize

Best for: very long conversations. Downside: extra LLM calls, and small details can be lost in the summary.

4️⃣ ConversationSummaryBufferMemory

A hybrid: keeps recent messages word for word, and summarizes older ones once the history passes a token limit.

Old messages
Compressed into a summary
+
Recent messages
Kept exactly (within max_token_limit)
from langchain.memory import ConversationSummaryBufferMemory memory = ConversationSummaryBufferMemory(llm=llm, max_token_limit=200)

Best for: production chatbots, because it balances exact recent context with a low token cost.

📝 Version note: These classes are legacy. The imports above (from langchain.memory ..., from langchain.chains ...) work in LangChain 0.x. In LangChain 1.0+ they moved to the langchain-classic package: pip install langchain-classic, then from langchain_classic.memory import ConversationBufferMemory. The ideas (buffer, window, summary) are still how modern memory works.

✅ Modern Way: RunnableWithMessageHistory

Wraps any chain and automatically loads / saves chat history per session_id, so different users get separate conversations.

from langchain_core.chat_history import InMemoryChatMessageHistory from langchain_core.runnables.history import RunnableWithMessageHistory from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder store = {} # session_id -> history def get_history(session_id: str): if session_id not in store: store[session_id] = InMemoryChatMessageHistory() return store[session_id] prompt = ChatPromptTemplate.from_messages([ ("system", "You are a helpful assistant."), MessagesPlaceholder("history"), ("human", "{input}"), ]) chat = RunnableWithMessageHistory( prompt | llm, get_history, input_messages_key="input", history_messages_key="history", ) config = {"configurable": {"session_id": "sai"}} chat.invoke({"input": "Hi, I'm Sai"}, config=config) chat.invoke({"input": "What's my name?"}, config=config) # -> "Your name is Sai"
Keeping history short: use trim_messages from langchain_core.messages to keep only the last N tokens (like BufferWindowMemory). For saving history to disk, swap InMemoryChatMessageHistory for Redis, SQL or file-based histories. For agents, LangGraph checkpointers are the recommended memory.

📚 RAG: Retrieval-Augmented Generation

LLMs don't know your documents. RAG finds the most relevant pieces of your data and puts them in the prompt, so the model answers from facts instead of guessing.

Part 2: Retrieval & Generation (every question)

→
Retrieve

→
Generate

Step 1: Document Loaders
from langchain_community.document_loaders import PyPDFLoader, WebBaseLoader, TextLoader, CSVLoader docs = PyPDFLoader("ml_notes.pdf").load() # one Document per page docs = WebBaseLoader("https://example.com/blog").load() docs = TextLoader("notes.txt").load() print(docs[0].page_content[:200]) # the text print(docs[0].metadata) # {'source': 'ml_notes.pdf', 'page': 0}
Step 2: Text Splitters
from langchain_text_splitters import RecursiveCharacterTextSplitter splitter = RecursiveCharacterTextSplitter( chunk_size=1000, # characters per chunk chunk_overlap=200, # overlap so sentences aren't cut in half ) chunks = splitter.split_documents(docs)
Why split? Small chunks = more precise search and they fit in the context window. RecursiveCharacterTextSplitter tries to split on paragraphs, then sentences, then words. Other splitters exist for Markdown, code, HTML and tokens.
Step 3 & 4: Embeddings + Vector Store
from langchain_openai import OpenAIEmbeddings from langchain_community.vectorstores import FAISS embeddings = OpenAIEmbeddings(model="text-embedding-3-small") # FREE alternative that runs locally: # from langchain_huggingface import HuggingFaceEmbeddings # embeddings = HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2") vectorstore = FAISS.from_documents(chunks, embeddings) vectorstore.save_local("faiss_index") # reuse later with FAISS.load_local vectorstore.similarity_search("What is gradient descent?", k=3)
Vector storeGood for
FAISSFast, local, in-memory, great for learning
ChromaLocal with persistence, easy setup
Pinecone / Weaviate / QdrantManaged, scalable production databases
pgvectorIf you already use PostgreSQL
Step 5: Retriever
retriever = vectorstore.as_retriever(search_kwargs={"k": 4}) # MMR = relevant AND diverse results (less repetition) retriever = vectorstore.as_retriever(search_type="mmr", search_kwargs={"k": 4}) retriever.invoke("What is backpropagation?") # -> list of Documents
Step 6: The Full RAG Chain
from langchain_core.prompts import ChatPromptTemplate from langchain_core.output_parsers import StrOutputParser from langchain_core.runnables import RunnablePassthrough prompt = ChatPromptTemplate.from_template("""Answer the question using ONLY the context below. If the answer isn't in the context, say "I don't know". Context: {context} Question: {question}""") def format_docs(docs): return "\n\n".join(doc.page_content for doc in docs) rag_chain = ( {"context": retriever | format_docs, "question": RunnablePassthrough()} | prompt | llm | StrOutputParser() ) print(rag_chain.invoke("What is gradient descent?"))
Advanced Retrieval Techniques
  • MultiQueryRetriever: LLM rewrites the question several ways and merges the results.
  • EnsembleRetriever: combine keyword search (BM25) with vector search (hybrid search).
  • ContextualCompressionRetriever: re-rank results and keep only the relevant parts.
  • ParentDocumentRetriever: search small chunks, return the bigger parent section.
  • Agentic RAG: let an agent decide when to search and re-search (built with LangGraph).

🛠️ Tools & Agents

A tool is a function the LLM can ask to run. An agent is an LLM in a loop that decides which tools to call until the task is done.
Creating a Tool with @tool
from langchain_core.tools import tool @tool def multiply(a: int, b: int) -> int: """Multiply two numbers.""" # the docstring tells the LLM what the tool does return a * b @tool def get_weather(city: str) -> str: """Get the current weather for a city.""" return f"It's 28°C and sunny in {city}." print(multiply.name, multiply.description, multiply.args)
Tool Calling: the model asks, your code runs
llm_with_tools = llm.bind_tools([multiply, get_weather]) msg = llm_with_tools.invoke("What is 12 times 7?") print(msg.tool_calls) # [{'name': 'multiply', 'args': {'a': 12, 'b': 7}, 'id': 'call_abc'}] # run the tool and send the result back result = multiply.invoke(msg.tool_calls[0]) # -> ToolMessage(content='84')
Important: the LLM never runs code itself. It only returns which tool to call and with what arguments. Your program runs the tool and sends the result back as a ToolMessage.
The Agent Loop (ReAct: Reason + Act)
Think
LLM decides next step
→
Act
Call a tool
→
Observe
Read tool result
🔁
Answer
When no more tools are needed
Building an Agent: create_agent (LangChain 1.0)
from langchain.agents import create_agent agent = create_agent( model="openai:gpt-4o-mini", tools=[multiply, get_weather], system_prompt="You are a helpful assistant. Use tools when needed.", ) result = agent.invoke({ "messages": [{"role": "user", "content": "What's the weather in Hyderabad, and what is 12 x 7?"}] }) print(result["messages"][-1].content)
create_agent runs on LangGraph under the hood, so it supports memory (checkpointers), streaming and human-in-the-loop. Older code used AgentExecutor + create_tool_calling_agent; these now live in langchain-classic.
Ready-made Tools
  • Web search: Tavily, DuckDuckGo, Google Search
  • Knowledge: Wikipedia, Arxiv
  • Code: Python REPL (be careful, it runs real code)
  • Data: SQL database toolkit, CSV / Pandas agents
  • Retriever as a tool: let the agent search your vector store

📡 Streaming, Callbacks & LangSmith

Streaming

Show the answer as it's being written (like ChatGPT) instead of waiting for the whole reply.

chain = prompt | llm | StrOutputParser() for chunk in chain.stream({"topic": "transformers"}): print(chunk, end="", flush=True) # Fine-grained events from every step (great for UIs) async for event in chain.astream_events({"topic": "RAG"}, version="v2"): if event["event"] == "on_chat_model_stream": print(event["data"]["chunk"].content, end="")
Callbacks

Hook into events like "LLM started" or "LLM finished" for logging, cost tracking, or progress bars.

from langchain_core.callbacks import BaseCallbackHandler class LoggingHandler(BaseCallbackHandler): def on_llm_start(self, serialized, prompts, **kwargs): print("🚀 LLM started") def on_llm_end(self, response, **kwargs): print("✅ LLM finished") chain.invoke({"topic": "LoRA"}, config={"callbacks": [LoggingHandler()]})

Best Practices
  • 🔑 Never hardcode API keys: use environment variables or a .env file.
  • 🌡️ Use temperature=0 for factual / structured tasks.
  • 📏 Watch token usage: trim chat history and keep chunks small.
  • ✅ Prefer with_structured_output over parsing free text.
  • 🔍 Turn on LangSmith early: it saves hours of debugging.
  • 🆓 Learn for free with Ollama + LLaMA and HuggingFace embeddings.
  • 🕸️ When you need loops, branching or human approval, move to LangGraph.
